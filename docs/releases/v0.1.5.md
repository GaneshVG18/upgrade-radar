# Upgrade Radar v0.1.5

This release hardens the zero-config review path and makes unsupported dependency upgrades useful without weakening the evidence model.

## What changed

- manifest/lockfile disagreement is now a visible coverage gap and incomplete report instead of a false clean result;
- packages without bundled reviewed notes now get resolved source-usage locations as `unknown` manual review starting points;
- `notes scaffold` creates a reviewed-note skeleton without fetching the supplied source URL;
- user-supplied reviewed notes can pair with the generic adapter for bounded live Jev judgment, while deterministic baseline keeps generic relevance `unknown`;
- first-class transition coverage now includes Express `4.21.2 → 5.1.0`, Zod `3.25.76 → 4.1.5`, Glob `8.1.0 → 10.4.5`, and Commander `11.1.0 → 12.1.0`;
- the compatibility corpus now contains 60 authored cases across 10 behavior families, including executable positive/negative assertions and explicit unknowns;
- Node support is `>=24`, with CI covering Node `24.11.1` and `25.x`;
- the standalone report has a compact retro workbench UI, composable filters, no-match recovery, unique evidence targets, truthful run context, mobile layout, and offline-only resources;
- the checked-in demo is generated from the current renderer and is publishable through GitHub Pages.

## Verification

Before tagging, the full `npm run check` gate passed locally on Node `24.11.1` and Node `25.2.1`. The gate covers typecheck, lint, unit/integration tests, the compatibility corpus, build, smoke, and a production-only package install with zero-config review.

Four external scratch-repository acceptance scenarios were also exercised: a supported Express upgrade, an unsupported React upgrade with generic usage starting points, a manifest/lock disagreement, and a repository with no dependency changes.

`npm audit --omit=dev` is clean. Historical package versions remain pinned only in dev dependencies to execute old/new behavior proofs.

The report remains advisory. `no_direct_evidence` is scoped to one reviewed note/site pair and is never a compatibility approval. Missing evidence remains visible as `unknown`.
